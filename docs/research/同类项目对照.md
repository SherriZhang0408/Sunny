## 1. 最接近的仓库（控制面近亲）



### 1.1 agentic-community/mcp-gateway-registry


| 项   | 内容                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------- |
| 地址  | [https://github.com/agentic-community/mcp-gateway-registry](https://github.com/agentic-community/mcp-gateway-registry) |
| 文档  | [https://agentic-community.github.io/mcp-gateway-registry/](https://agentic-community.github.io/mcp-gateway-registry/) |
| 星标  | 934（Fork 239，Watch 9）                                                                                                  |
| 许可  | Apache-2.0                                                                                                             |
| 栈   | FastAPI 控制面 + nginx 数据面 + Keycloak/Entra/Okta + MongoDB                                                                |
| 定位  | 企业 AI 资产总目录：MCP Server、A2A Agent、SKILL.md、自定义实体                                                                        |


**仓里有什么**

- 登记 / 发现 / 鉴权 / 审计一条控制面；默认 **A2A 对等直连**，网关可选（reverse-proxy mode）。
- 发现面三种：UI、REST、内置 MCP server（`airegistry-tools`：`search_registry`、`list_agents`）。
- 语义 + 词法搜索；登记扫描 + fail-closed webhook；联邦拉 Anthropic / 官方 MCP Registry / 对等仓。
- 限流、隔离（quarantine）、per-user egress OAuth、OpenTelemetry。
- 公开页自我定位仍可当「任意 HTTP 的 AI 网关」：模型推理、MCP、A2A、通用 REST 都能挂到同一入口。这是它的产品野心，不是 Sunny 的 P0。
- 理论文档强调：控制面管库存和策略，数据面才转发。

**可借鉴**

- 资产分型，禁止 Agent / MCP / Skill 混一张无类型表（Sunny 立项已红线，Hub 应显式分栏）。
- 把 **search / get_card** 暴露成 MCP tool，Hermes 不必先学 `sunny_client`。
- 登记准入扫描（密钥、危险 URL）；继续做校验器，不要做工作流引擎。
- 默认 P2P，印证 ADR-001「Registry 不转发」。
- 联邦入口以后若要拉官方 MCP Registry，应当「摄入源」而不是把 Sunny 改造成 MCP 应用商店。

**不要学**

- 一上来自研整包网关 + IdP + Mongo。
- 把模型推理、任意 REST 都收进同一个网关当 P0。

**对 Sunny 的落点**

- P1：MCP 发现面、目录分型、扫描加强。
- 数据面以后接 [agentgateway](https://github.com/agentgateway/agentgateway)，不必抄它的 nginx 方案。
- `approval_required` 人审闸已落地（学其「准入」叙事，不是抄 webhook 引擎）。

### 1.2 Nacos 3.1+ Agent 管理（A2A Registry）


| 项      | 内容                                                                                                                                           |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 仓      | [https://github.com/alibaba/nacos（整仓](https://github.com/alibaba/nacos（整仓) 33.4k★ / 13.3k fork；Apache-2.0）                                   |
| 文档     | [https://nacos.io/en/docs/latest/manual/user/ai/agent-registry/](https://nacos.io/en/docs/latest/manual/user/ai/agent-registry/)             |
| 总览     | [https://nacos.io/en/docs/latest/manual/user/ai/ai-registry-overview/](https://nacos.io/en/docs/latest/manual/user/ai/ai-registry-overview/) |
| 仓内相关目录 | `ai/`、`ai-registry-adaptor/`、`skills/nacos-skill-registry/`                                                                                  |
| 配套运行时  | [https://github.com/agentscope-ai/agentscope-runtime](https://github.com/agentscope-ai/agentscope-runtime) （869★，可插拔 Registry）               |
| 版本线索   | 3.1.0 起 Agent Registry；[3.2.0](https://github.com/alibaba/nacos/releases) 强化插件化与 AI Registry；文档示例 Client 已写到 `3.2.3`                         |
| 定位     | 国内企业默认「智能体注册中心」：AgentCard 发布、发现、命名空间、版本                                                                                                      |


**仓 / 产品里有什么**

- HTTP Admin API + gRPC / Java SDK 发布、查询、**订阅** AgentCard；控制台「Agent Registry → Agent List」。
- 命名空间硬隔离：`(namespaceId, name)` 唯一；同名可跨命名空间。名称 ≤ 64，仅可见 ASCII。
- 多版本：每次改 Card 必须发新 `version`；消费者默认拿「当前发布版」，也可点名版本。
- 资源分型：Agent / MCP / Skill / Prompt。3.2 另开 **Skill Registry**（企业 Skill 包治理，和 Agent 列表不是同一件事）。
- 发布路径三条：Spring AI Alibaba 自动挂号、Java `AiService.releaseAgentCard` + `registerAgentEndpoint`、控制台 / HTTP 导入外部供应商。
- 控制台 JSON 导入仍写「开发中」；现网导入走 HTTP `POST /nacos/v3/admin/ai/a2a`。
- **按 skill / tag / 描述模糊搜仍在路线图**（2026 latest 文档原话，未因 3.2 Skill Registry 自动完成）。
- SDK 仍偏 Java；Python/Go 在做。官方会跟 [A2A Registry Protocol 讨论 #741](https://github.com/a2aproject/A2A/discussions/741)，标准出来再适配。
- 订阅不是轮询：`subscribeAgentCard` 在 Card 升版或 endpoint 变化时回调，调用方更新本地 A2A Client。

**可借鉴**

- 订阅推送：Card 升版后调用方不用盲等心跳。Sunny 升 `version` 已作废旧票，缺的是推给对等方。
- 命名空间 ≈ Sunny `workspace`，但 Nacos 是硬隔离，Sunny P0 是标签。
- 「Card 与 endpoint 分开登记」：`releaseAgentCard` + `registerAgentEndpoint`。Sunny 的 sidecar 心跳已经在报活，可对照「endpoint 变更也推」。
- 运行时自动挂号（AgentScope / Spring AI Alibaba）对 S1 sidecar 仍有启发。

**不要学**

- 把 Nacos 整包搬进 Python 仓当第一依赖。
- 叙事绑死「必须先当 A2A Server」。Sunny 的切口是已有 HTTP + sidecar。
- 用 33.4k 星当「Agent Registry 已经赢了」——那是整个微服务配置中心的星。

**对 Sunny 的落点**

- 订阅 / 推送仍是 P2。P0 的 stale 过滤、Card URL 探活已落地。
- skill / tag 过滤 Nacos 自己都还没做完，Sunny 不必等人家发版。

### 1.4 prassanna-ravishankar/a2a-registry


| 项   | 内容                                                                                                             |
| --- | -------------------------------------------------------------------------------------------------------------- |
| 地址  | [https://github.com/prassanna-ravishankar/a2a-registry](https://github.com/prassanna-ravishankar/a2a-registry) |
| 站点  | [https://a2aregistry.org](https://a2aregistry.org) （API 文档 `/api/docs`，MCP `/mcp/`）                            |
| 星标  | 25（Fork 45，224 commits）                                                                                        |
| 许可  | MIT                                                                                                            |
| 栈   | FastAPI + Postgres（Cloud SQL）+ 后台 worker + React + Helm / GKE Autopilot                                        |
| 定位  | 公网活体 A2A 目录；登记处自己也是 A2A Agent                                                                                  |
| 客户端 | PyPI `a2a-registry-client`                                                                                     |


**仓里有什么**

- `POST /agents/register` 只收 `wellKnownURI`，worker 拉 `/.well-known/agent-card.json`（README 示例偶发写成 `agent.json`，解析应对两种）。
- **三质量信号**（最值得抄）：
  - `is_healthy`：Card URL 30 分钟探一次，要合法 JSON。
  - `conformance`：schema 是否像 A2A。
  - `task_conformance` / `task_verified`：每日真发 `message/send`（Sunny **不要**默认代发业务）。失败分类挂在 `task_conformance.category`（`WORKING` / `404` / `401` / `TIMEOUT` / `NO_TRANSPORTS` …）。
- 过滤：`search`、`skill`、`capability`、`author`、`conformance`、`task_verified`。
- 另有 `GET /agents/{id}/health`、`/uptime`；`PUT` 管理员重抓；`DELETE` 要所有权。
- `POST /agents/{id}/chat` **代理对话**。
- 探活 UA：`A2A-Registry-TaskProbe/1.0`（日跑）、`A2A-Registry-Smoke/1.0`（登记烟测）。Sunny 已用 `SUNNY-Registry-Pull/1.0`。

**可借鉴**

- Well-Known 拉取登记（已落地）：同事只给基址，Hub 拉卡、周期重抓。与 Join Packet 互补。
- 健康 / schema / 入口可达 三信号。第三层在 Sunny 应探 sidecar `/health` 或 Card 接口 URL，**不要** `message/send`。
- 探活 User-Agent 写清楚，方便对端识别。
- `task_conformance.category` 这种「失败有名字」比布尔 `online` 更利于 Hub 对账；Sunny 观测时间线可以朝这个方向长，但不要上日跑业务探针。

**不要学**

- 「我们信任 Agent Card」——企业内网相反：人审 + 拒密钥 + 策略门闩。
- Registry 代理 `/chat`，违反 ADR-001。

**对 Sunny 的落点**

- P0：Card URL 探活、Well-Known 拉取均已落地。见 [week-well-known-pull](../plans/week-well-known-pull.md)、[well-known-pull](../specs/well-known-pull.md)。

### 1.5 c-daniele/agent-reg


| 项   | 内容                                                                               |
| --- | -------------------------------------------------------------------------------- |
| 地址  | [https://github.com/c-daniele/agent-reg](https://github.com/c-daniele/agent-reg) |
| 星标  | 3（Fork 1，**仅 3 次提交**）                                                            |
| 许可  | MIT                                                                              |
| 栈   | FastAPI 3.8+、SQLite JSON、React 18 + Tailwind + Axios                             |
| 定位  | 最小 A2A Registry：登记、心跳、按 skill 搜                                                  |


**仓里有什么**

- `POST /agents/register` 交整张 Card；对照 `a2a_agent_card_schema.json`，不合格 `422`。
- `GET /agents?name=&skill=&owner=&capabilities=&only_alive=true`（5 分钟内心跳）。
- `POST /agents/{id}/heartbeat`；`GET /agents/{id}/invoke_url`。
- 口头支持 OAuth2 / API Key / mTLS / JWS——都是 **Card 字段能描述**，仓本身没有调用票、副作用门闩、sidecar、工作空间。
- 结构很薄：`backend/app` + `frontend`，适合当「同栈对照标本」，不是生产参考实现。

**可借鉴**

- `only_alive`**：搜索默认排除心跳过期。** Sunny 已落地：`/search` 默认只要 `runtime_status=online`，管理员可 `alive=0`。
- `capabilities`、`owner` 过滤可作 P2。
- 同栈对照：用来确认 Sunny 多出来的票、门闩、Join Packet、sidecar 不要拆掉。

**不要学**

- 看见 Card 就能调（只给 invoke_url）。
- 无 RBAC、无观测时间线。
- 把「支持 OAuth / mTLS」写进 README 就当自己做了鉴权。

**对 Sunny 的落点**

- P0 已齐。票和门闩继续守住。

### 1.6 agentoperations/agent-registry（本轮新列入近亲）


| 项   | 内容                                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 地址  | [https://github.com/agentoperations/agent-registry](https://github.com/agentoperations/agent-registry)                                   |
| 演示  | [https://agentoperations.github.io/agent-registry/presentation.html](https://agentoperations.github.io/agent-registry/presentation.html) |
| 星标  | 6（Fork 2，11 commits，v0.1.0 演示视频）                                                                                                         |
| 许可  | 公开页未见 LICENSE 文件，引用前先核                                                                                                                   |
| 栈   | Go + Chi + SQLite（可换 Postgres）+ 嵌入式目录 UI；K8s / OpenShift overlay                                                                         |
| 定位  | 厂商无关的元数据仓：A2A AgentCard + MCP `server.json` + Agent Skills；**不存二进制、不算信任分**                                                               |


**仓里有什么**

- 三种制品共用治理：BOM、外部评测记录、晋升历史、依赖图。身份格式仍用开放标准，Registry 只回答「该不该信、依赖谁、谁说能上」。
- 晋升状态机：`draft → evaluated → approved → published → deprecated → archived`。`evaluated` 之后内容不可变。没有内置门闩策略，留给外部 policy。
- `agentctl import --from-a2a https://…/.well-known/agent-card.json`；`get --format a2a` 再导出纯 Card。
- `eval attach` 只收外部工具分数（Garak 等），自己不跑评测。
- API 在 `/api/v1`，错误走 RFC 7807；`GET /search?q=` 跨类型全文搜。
- 二进制留在 ghcr / quay / ECR。CLI 是瘦客户端，逻辑全在服务端。

**可借鉴**

- **分型 + 晋升** 比「一张 agents 表 + 布尔上架」更接近企业策展。Sunny 已有 `approval_status`（pending/approved/rejected），不必一次抄六态，但 `deprecated` / 「通过后升 version 才不可改」值得对照。
- Well-Known **导入 / 导出** 与 Sunny `pull` / `refresh` 同构：标准文档进，标准文档出，治理字段不回写进对端 Card。
- 评测当外部信号、Registry 不算分——和 Sunny「探活不代发业务」同一原则。
- Hub 分栏（Agent / 以后的 MCP / Skill）可直接引用它的 Kind 表。

**不要学**

- 用 LLM `agentctl init` 扫仓库生成 Card 当默认登记路径。
- 把 OCI 引用做成身份主键；Sunny 的主键仍是 `agent_id`。
- 一上来上 OpenShift / distroless 发布面。

**对 Sunny 的落点**

- 对照用，不引入 Go 栈。审批已落地的三态先用着；若第二户要「上架生命周期」，再评估是否加 `deprecated`。

**产品里有什么**

- 协作原语：`Space → Category → Channel → Thread`。人和 Bot **共用同一套频道**，没有单独「AI 界面」。把 Agent 拉进频道即上线。
- 工作单元 **Matter**：从讨论里结晶出来（先聊后单），带 owner、交付物、执行日志、验收。时间线可审计。
- Bot 带 **AgentCard**（能力、框架、履历、任务类型）。官方说可接 OpenClaw、Hermes、Codex、Claude Code。
- 人审沉淀为 **Preference Card**（规则、适用范围、证据、置信度）；方法可再结晶成组织 **Skill**。
- 多 Agent 信息流模式（DEV.to）：Solo / Roundtable / Critic / Pipeline / Split / Swarm——管的是可见性与上下文怎么流，不是 Registry 出票。
- 浏览器扩展 Cmd+K：网页选区带 URL/标题拉进频道。`group.md` 做结构化对齐。
- 三条 Agent 法则：不伤尊严 → 对 Owner 透明 → 知识署名（公开自由 / 内部标注作者 / 隐性知识最高保护）。
- `octo-server` 请求路径：鉴权 → 组织 RBAC / 频道 ACL / **agent-identity gating** → 业务或拉起 Lobster session → IM 扇出 → adapter。存储 MySQL + Redis；对象存储可插拔。
- `octo-cli`：`bot` 域含 register / heartbeat；token 分 `app_*` / `bf_*` / `uk_*`；能力门闩在服务端（`FORBIDDEN`），CLI 本地几乎不执法。错误 taxonomy 固定，exit 3=auth、2=validation。

**和 Sunny 差在哪一层**


|            | Octo                                       | Sunny                                                        |
| ---------- | ------------------------------------------ | ------------------------------------------------------------ |
| 回答的问题      | 人和 Agent 怎么在同一频道里干活                        | 企业里谁在、会什么、哪条 skill 能开票                                       |
| 默认界面       | IM                                         | Hub 目录 + REST / MCP 发现                                       |
| Agent 怎么进来 | 拉进频道；adapter 接到 OpenClaw / Hermes **聊天通道** | Card 登记 + sidecar；Hermes 用 `sunny.discover` / `sunny.invoke` |
| 「Card」     | Bot 的协作身份 + 履历                             | A2A 对齐的发现面；`restricted` 只披露、对等不出票                            |
| 人的位置       | Taste：频道里品鉴、Preference Card                | 策展：审批上架、副作用门闩、管理员代签                                          |
| 红线         | 把组织变成 Agent 互联网                            | Registry **不转发**、不做 `/chat`                                  |


**可借鉴（叙事与少数控制面手法，不抄产品）**

- **「工具留在原处」**：和 ADR-001 sidecar 同构。Sunny 继续不吞文档仓 / 看板 / Hermes 内核。
- **人负责判断**：Octo 的 Taste ≈ Sunny 已落地的 `approval_required` + 对等拒 `write` / `restricted`。不必再做 Preference Card 引擎；Hub 审批理由、Card `when_not_to_use` 已经是「人的品味」落点。
- **给 Agent 用的无交互 CLI**：`sunny_client` / Join Packet 已是机器可读。以后若加 CLI 子命令，学它的 JSON envelope + 错误分类 + `--dry-run`，不要学 48 个文档/网盘域。
- **Bot 心跳 / 登记写进 CLI 域**：对照 Sunny `POST /heartbeat` + enroll。他们能力执法在服务端——和票门闩在 Registry 一致。
- **Adapter 可插拔、不改核心**：对照 `sunny_adapter` 映射 HTTP。Octo 的 Hermes **channel** 是把 Hermes 拖进 IM；Sunny 的 Hermes Skill 是让 Hermes 来搜目录。方向相反，不要接错。
- **Space 硬隔离**：对照 `workspace`（Sunny 仍是标签，不是 Nacos 式硬隔离）。
- **透明可审计**：频道里看见每一步 ≈ Sunny 观测时间线按 `trace_id` 对账。学「失败/步骤有名字」，不要学「Registry 转发推理过程」。

**不要学**

- 把 Hub 做成 IM / 龙虾编排器 / 六种协作模式 / Marketplace。
- 上 WuKongIM、Electron、iOS/Android、浏览器扩展当 P0。
- 用 LLM 从聊天抽 Matter 当登记或出票入口。
- 把 `octo-adapters` 的 Hermes channel 接到 Sunny——那会把对话面和发现面焊死，违反「图像/闭环不经 SUNNY」。
- 被「全球首个开源可信 Agent 协作网络」的发布文案带跑：那是编排产品，星标也主要在客户端仓。

**对 Sunny 的落点**

- **对照用，不引入。** 控制面缺口还剩订阅 / `deprecated`，不是频道和 Matter。
- 若业务仓（Hermes）有人要「群里叫多个 Agent」，那是 Octo / CrewAI 的层，应在 Hermes 或独立协作栈做；Sunny 只继续提供搜卡、出票、直打 sidecar。

## 3. Sunny 已经强过多数同栈仓的点

- 发现 ≠ 访问：短时票绑 caller + skill + `card_version`。

- 技能副作用门闩：`write` / `execute_sql` / `restricted` 不对等搜索。
- Join Packet：给其他 Agent 的自包含接入说明。

- 搜索排除心跳过期；Card URL 探活；Well-Known 拉取；`approval_required` 人审（开发者不能自审通过）。
