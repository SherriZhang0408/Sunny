1. 推荐启动顺序

Registry 必须先起。Adapter 起来后会 enroll / 心跳。Client 是一次性命令，不是常驻进程。Hub 不单独起，跟 Registry 同进程。

1. python3 -m sunny_registry
2. python3 -m sunny_adapter
# 第二户（可选）
3. python3 -m sunny_echo
4. ECHO_URL=http://127.0.0.1:8092 \
   SUNNY_ADAPTER_CARD=cards/lab.echo.sample.json \
   SUNNY_ADAPTER_MAPPING=sunny_adapter/mappings/lab.echo.json \
   SUNNY_ADAPTER_AGENT_ID=lab.echo \
   SUNNY_ADAPTER_PORT=8093 \
   python3 -m sunny_adapter
5. python3 -m sunny_client --skill collect.strategy.query --slots '{"mission_name":"living_room"}'
服务默认端口成功探活
Registry + Hub8088GET /api/v1/health → ok: true
Adapter Hermes8091GET /health → enrolled: true
Echo HTTP8092GET /health → ready: true
Adapter lab.echo8093GET /health → mapping.ok

监听默认 0.0.0.0。浏览器和名片里的基址用局域网 IPv4 或 127.0.0.1，不要写 0.0.0.0。前台终端被 abort 会带走进程，生产/联调用 setsid 拉起。

2. Registry + Hub

入口 python3 -m sunny_registry。无 CLI 参数，全靠环境变量。管理台静态页同进程提供，打开 http://127.0.0.1:8088。

变量默认用途
SUNNY_HOST / SUNNY_PORT0.0.0.0 / 8088监听
SUNNY_PUBLIC_URL空则推局域网 IPv4握手包与名片基址
SUNNY_DBdata/sunny.dbSQLite
SUNNY_SEED1（0 关）空库种 aidata.hermes + lab.inspector
SUNNY_ADMIN_TOKENsunny-dev-admin管理员 Bearer；也是 Hub admin 密码
SUNNY_DEVELOPER_PASSWORDsunny-dev-developerHub developer 密码
SUNNY_ENROLL_TOKENsunny-dev-enroll自注册 X-Sunny-Enroll
SUNNY_TICKET_SECRETsunny-dev-ticket调用票与会话签名
SUNNY_TICKET_TTL_S300调用票秒数
SUNNY_SESSION_TTL_S43200Hub 会话秒数
SUNNY_HEARTBEAT_STALE_S90超时标 stale，搜索默认排除
SUNNY_PROBE_TIMEOUT_S2Card URL 探活
SUNNY_PULL_TIMEOUT_S5Well-Known 拉取
SUNNY_SWEEP_S60（pytest 下 0）周期探活/重抓；0 关
SUNNY_REFRESH_INTERVAL_S300有 card_source_url 才重抓

启动

python3 -m pip install -r requirements.txt
SUNNY_SEED=1 python3 -m sunny_registry

成功判定

  • GET /api/v1/health 含 ok: true、service: sunny-registry、public_url、fts.ready、sweep
  • 浏览器打开 / 看到登录页（#/login）；默认账号 admin / 上表管理员口令
  • 空库且 SUNNY_SEED=1 时库里有演示对；缺样例卡则跳过演示对，进程仍能起

依赖：无其他 SUNNY 进程。Hub 静态资源来自 web/。

3. Adapter（Hermes / aidata.hermes）

入口 python3 -m sunny_adapter。先起 Registry。默认挂 aidata.hermes，端口 8091。Hub 已有同一 agent_id 时只挂接口，不改 enrollment_source。

变量默认用途
SUNNY_REGISTRY_URLhttp://127.0.0.1:8088Registry 基址
SUNNY_ADAPTER_HOST / PORT0.0.0.0 / 8091监听
SUNNY_ADAPTER_PUBLIC_URL局域网 IP + :8091/sunny/v1写入 Card 的对外接口
SUNNY_ADAPTER_CARDcards/aidata.hermes.sample.json挂载名片
SUNNY_ADAPTER_AGENT_IDaidata.hermes标识
SUNNY_ADAPTER_MAPPINGsunny_adapter/mappings/aidata.hermes.json（文件存在才加载）技能路由
SUNNY_ADAPTER_KEY_FILEdata/adapter-keys/<id>.key持久化 sak_
SUNNY_AGENT_KEY空已有 key 可跳过签发
SUNNY_ADMIN_TOKEN / SUNNY_ENROLL_TOKEN与 Registry 相同开发值409 后 attach / 首次自注册
SUNNY_ADAPTER_HEARTBEAT_S30心跳间隔
SUNNY_ADAPTER_ENROLLMENTself注册来源字段
AIDATA_ROOT本机 AIDataAgent 路径有包装器才真 collect.volume.query

启动

python3 -m sunny_adapter

成功判定

  • GET /health：ok: true、enrolled: true
  • 匿名可打开 /.well-known/agent-card.json（与 /agent.json、/sunny/v1/card 相同，带 ETag）
  • Hub 上该卡 online；钥匙在 data/adapter-keys/aidata.hermes.key（不进 Git）
  • collect.strategy.query 进程内枚举即可调通；volume 无包装器时 ready=false mock=true 仍算调通

依赖：必须先有 Registry。可选 AIDataAgent 包装器。

4. Echo HTTP + Echo sidecar

第二户。回声进程不验票；验票在 :8093 的 sidecar。映射里的 ${ECHO_URL} 不是 AdapterSettings 字段，要自己 export。

模块变量默认
echoSUNNY_ECHO_HOST / SUNNY_ECHO_PORT0.0.0.0 / 8092
sidecarECHO_URL映射展开，常用 http://127.0.0.1:8092
sidecarSUNNY_ADAPTER_AGENT_IDlab.echo
sidecarSUNNY_ADAPTER_PORT8093（勿与 8091 冲突）
sidecarSUNNY_ADAPTER_CARDcards/lab.echo.sample.json
sidecarSUNNY_ADAPTER_MAPPINGsunny_adapter/mappings/lab.echo.json

启动

python3 -m sunny_echo
ECHO_URL=http://127.0.0.1:8092 \
SUNNY_ADAPTER_CARD=cards/lab.echo.sample.json \
SUNNY_ADAPTER_MAPPING=sunny_adapter/mappings/lab.echo.json \
SUNNY_ADAPTER_AGENT_ID=lab.echo \
SUNNY_ADAPTER_PORT=8093 \
python3 -m sunny_adapter

成功判定

  • Echo：GET :8092/health → ready: true；POST /v1/echo {"query":"hello"} 回显
  • Sidecar：GET :8093/health 含 mapping；python3 -m sunny_client --skill echo.ping --slots '{"query":"hello"}' 得 ready: true
  • echo.secret 只在 Extended Card，目录搜不到

依赖：Registry + echo HTTP + echo sidecar。钥匙 data/adapter-keys/lab.echo.key。本机若 :8092 已被占，先换 SUNNY_ECHO_PORT 并同步 ECHO_URL。

5. sunny_client

一次性 CLI：搜卡 → 出票 → 直打 sidecar。可选把结果报到 /invocations。不是常驻服务。

参数 / 变量默认用途
--skill必填技能 id
--slots{}JSON 对象；非法对象回码 1
--registry / SUNNY_REGISTRY_URLhttp://127.0.0.1:8088Registry
--callee空则按搜索结果指定被调方
--caller / SUNNY_CALLER_IDlab.inspector管理员代签时的 caller
SUNNY_AGENT_KEY空有则作 X-Sunny-Agent-Key
SUNNY_ADMIN_TOKENsunny-dev-admin无 agent key 时本机代签

启动

python3 -m sunny_client --skill collect.strategy.query --slots '{"mission_name":"living_room"}'
python3 -m sunny_client --skill echo.ping --slots '{"query":"hello"}'

成功判定：退出码 0，stdout 打印 JSON 结果。失败打 stderr，码 1。

依赖：Registry + 目标 sidecar。Hermes 对话不要直接跑这条；可选 Skill 走 python3 -m sunny_client.hermes discover|invoke，需 AIDATA_SUNNY=1 或 SUNNY_HERMES_SKILLS=1，默认关，不改 Hermes 内核。

6. validate_card.py

离线校验名片：JSON Schema + 禁密钥扫描。不需要 Registry。

启动

python3 scripts/validate_card.py cards/aidata.hermes.sample.json

成功判定：码 0 打印 OK …；schema / 密钥失败码 1；用法或文件不存在码 2。

依赖：sunny_registry.card_validate。样例卡本机可有，仓内 cards/ 只跟踪 .gitkeep。

7. MCP stdio

入口 python3 -m sunny_registry.mcp_stdio。把 stdin JSON-RPC 转到 Registry POST /mcp。只发现，不签发票、不代调。

变量默认用途
SUNNY_REGISTRY_URLhttp://127.0.0.1:8088转发目标
SUNNY_AGENT_KEY空Header X-Sunny-Agent-Key
SUNNY_AGENT_KEY_FILE—从文件读 key；路径含 scratch 会退出

启动（Cursor 等客户端挂 command，不要当普通 HTTP 服务）

SUNNY_REGISTRY_URL=http://127.0.0.1:8088 \
SUNNY_AGENT_KEY=sak_… \
python3 -m sunny_registry.mcp_stdio

成功判定：无 banner。向 stdin 写 Content-Length 帧，stdout 回 JSON-RPC。也可先 GET /mcp 看工具清单（匿名）。除 join 外需 sak_ 或 Hub 会话。

依赖：Registry 已起。不要把 key 放进个人 scratch。

联调提醒：adapter 必须等 Registry 起来再拉，否则 enroll 心跳会 Connection refused。共享变量 SUNNY_REGISTRY_URL、SUNNY_ADMIN_TOKEN、SUNNY_ENROLL_TOKEN 跨进程保持一致。

对照合同：adapter.md、registry-api.md、mcp-discovery.md。接口分组见 API 文档。
