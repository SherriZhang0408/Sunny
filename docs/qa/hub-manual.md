# Hub 手工 QA 清单

| 项 | 内容 |
|----|------|
| 对象 | SUNNY 管理台（`web/`，Registry 同进程静态页） |
| 不是 | `tests/test_hub_ui.py`（那只检查 HTML/CSS/JS 能被端出来） |
| 角色 | [ADR-003](../decisions/ADR-003-Hub角色权限.md)：`admin` 全权限；`developer` 看卡 + 维护自己发布的卡 |
| 过线 | 每一节主路径 + 标明的失败路径都点过；登录态换页不丢；页面上**没有** `sak_` / 完整调用票 / 密码 |

勾选用例时写日期、浏览器、账号角色。不要把票、key、密码贴进本文件或截图仓库。

## 0. 开测前

- [ ] Registry 用脱离会话的方式拉起（前台终端被 abort 后 `:8088` 会断）：

```bash
cd ~/PycharmProjects/Sunny
setsid -f python3 -m sunny_registry
curl -sS http://127.0.0.1:8088/api/v1/health
```

- [ ] 浏览器打开 `http://127.0.0.1:8088`（局域网用握手包里的 IPv4，不要用名片里的 `0.0.0.0`）
- [ ] 桌面宽度（约 1280）走完全部节；改过布局再看一版窄窗（约 390）
- [ ] 中文不是方框（缺字体时会花屏；页面已挂 Noto Sans SC）
- [ ] 本机默认账号（可用环境变量覆盖，见 ADR-003）：`admin` / `sunny-dev-admin`，`developer` / `sunny-dev-developer`
- [ ] 库里至少有 `aidata.hermes`（管理台填入）和一张别人的卡（如 `lab.inspector` / 开发者自己发的）才能做权限对照

## 4. 管理员：编辑（先用自己能改的卡，或开发者刚发布的测试卡）

**不要**在共享现网库上对 `aidata.hermes` 做不可逆删除。编辑/删除用一张专门登记的 QA 卡。

| # | 操作 | 期望 | 过 |
|---|------|------|----|
| 4.1 | 「编辑」或 Tab「编辑」 | `#/agents/<id>/edit`；可改名称 / 版本 / 说明 | ☐ |
| 4.2 | 改说明 →「保存修改」 | 成功后进该卡概览；说明已变；历史多一条更新 | ☐ |
| 4.3 | 「添加技能」再删掉（不保存或保存后还原） | 编辑器能增删技能块；副作用 / 数据分级是下拉 | ☐ |
| 4.4 | 输入槽填非法 JSON 保存 | 页内报错，卡还在 | ☐ |
| 4.5 | 「删除」→ 取消 | 弹层关，卡仍在目录 | ☐ |
| 4.6 | 「删除」→ 确认删除 | 回浏览目录，该 `agent_id` 消失（仅 QA 卡） | ☐ |

## 7. 管理员：发布登记 `#/publish`

| # | 操作 | 期望 | 过 |
|---|------|------|----|
| 7.1 | 打开发布 | 基址不是 `0.0.0.0`；有局域网候选（若 Join 有） | ☐ |
| 7.2 | 「导出接入说明」 | 下载 `sunny-join.md`；打开后**没有** enroll token | ☐ |
| 7.3 | 「导出含注册令牌」 | 下载 `sunny-join.secret.md`（勿提交 Git）；普通导出仍无 token | ☐ |
| 7.4 | 登记方式切到「智能体主动登记」 | 出现注册令牌密码框 | ☐ |
| 7.5 | 名片框贴一段坏 JSON → 登记 | 「JSON 无法解析」 | ☐ |
| 7.6 | 贴一份合法样例卡（先改成未占用的 `agent_id`，如 `qa.hub.manual`）→ 登记 | 弹层「Agent key 只显示这一次」；点「查看名片」进详情 | ☐ |
| 7.12 | 对等可见选「需审批后可见」再登记一张 QA 卡 | 目录徽章「待审批」；浏览筛「待审批」能看到 | ☐ |
| 7.7 | 浏览目录 | 新卡来源「管理台填入」，创建者是当前管理员 | ☐ |
| 7.8 | 「从 URL 拉取名片」空提交 | 「请填写基址或 Card URL」 | ☐ |
| 7.9 | 填 `file:///etc/passwd` 或 `http://169.254.169.254/` → 拉取登记 | 失败（禁非 http(s) / 元数据主机），不入库 | ☐ |
| 7.10 | 填本机 sidecar 基址（`SUNNY_ADAPTER_PUBLIC_URL` 的 origin，先换未占用 `agent_id`）→ 拉取登记 | 弹层有一次 `sak_`；详情有「名片来源 URL」和「刷新名片」 | ☐ |
| 7.11 | 改远端 Card 的 `version` 后点「刷新名片」 | 概览版本更新；失败时旧卡仍在 | ☐ |

第 7.6 / 7.10 的卡留给第 4 节删除，避免污染长期目录。

## 9. 开发者对照（换账号，不要复用管理员会话）

退出后用 `developer` 登录。

| # | 操作 | 期望 | 过 |
|---|------|------|----|
| 9.1 | 顶栏 | 有浏览目录、发布登记；**没有**调用关系、活动动态、账号 | ☐ |
| 9.2 | 手改 `#/network`、`#/activity`、`#/users` | 「开发者不能查看调用关系。」「开发者不能查看全局活动动态。」「只有管理员可以管理账号。」 | ☐ |
| 9.3 | 浏览 `aidata.hermes`（别人的卡） | 能看概览 / 名片 / 历史；**没有**编辑 Tab、编辑/删除/停用/心跳/出票 | ☐ |
| 9.4 | `#/publish` | **没有**「导出含注册令牌」、**没有**登记方式下拉（固定管理台填入）；有「从 URL 拉取名片」，**没有**补 `agent_id` 框；有「需审批后可见」 | ☐ |
| 9.9 | 开发者发一张「需审批后可见」的卡 | 自己能看见、能改说明；**没有**通过/拒绝；对等搜不到 | ☐ |
| 9.5 | 登记一张自己的卡（如 `qa.dev.manual`） | 成功；详情有编辑 / 删除；**仍没有**停用、心跳、出票 | ☐ |
| 9.6 | 改自己卡的说明并保存 | 成功；浏览里描述已变 | ☐ |
| 9.7 | 再开管理员会话看这张卡 | 管理员仍能停用/出票；创建者是 `developer` | ☐ |
| 9.8 | 开发者删自己的 QA 卡 | 目录消失 | ☐ |
