## 0. 三档技能（建议 id）


| skill.id                 | 名称     | 对标 ChatBI Lane | `side_effects`                            | 一期默认               |
| ------------------------ | ------ | -------------- | ----------------------------------------- | ------------------ |
| `chatbi.template.render` | L1 模板  | L1             | `read`（若打开执行则另议，仍不标 `execute_sql` 除非真跑查询） | **主路径，先填这张**       |
| `chatbi.kb.ask`          | 知识问答   | L4             | `read`                                    | 可并行                |
| `chatbi.sql.generate`    | 生成 SQL | L3 的「出计划」部分    | `read`                                    | 只出 SQL 计划，默认不执行    |
| `chatbi.sql.execute`     | 执行取数   | L3 执行          | `execute_sql`                             | **默认不进跨 Agent 搜索** |


「生成 SQL 取数」拆成 generate / execute，否则一张 skill 会把「看计划」和「借路查数」绑死，和现网「无业务行权限不许绕过」冲突。

## 1. L1 模板：八字段（搁置，不必现在填）

这些只有 ChatBI 同事看着 Gateway 才能填。恢复 M3 时再打开。


| #   | 字段     | 要什么                                                    | 同事填写 |     |
| --- | ------ | ------------------------------------------------------ | ---- | --- |
| 1   | 基址     | 内网 URL、环境（dev/生产分开）、谁运维                                |      |     |
| 2   | action | 显式动作名或模板 ID，禁止只给「把 query 丢进去」                          |      |     |
| 3   | 槽字典    | 必须能传入的键：身份（did/sn/iot 等价）、时间窗、模板参数；与 Association 对齐的注明 |      |     |
| 4   | 执行开关   | 默认是否执行 SQL；打开执行要书面授权                                   |      |     |
| 5   | trace  | 请求/响应里的 `trace_id` 字段名；能否回传 `lane` `status`            |      |     |
| 6   | 失败语义   | `clarify` / Guard 拒绝 / 超时 / 无权限 的 `status`；Hermes 如何降级 |      |     |
| 7   | 权限     | 服务账号还是网关 Token；表白名单；是否行级                               |      |     |
| 8   | 负责人    | 姓名 / 值道 / 发版联系人                                        |      |     |


建议先选 **一个** 已核表主题（宠物家 `pet_flag` 或配网）当第一个 `template_id`。

### L1 输入槽（SUNNY 侧预设，可改名对齐）

```json
{
  "template_id": "fs_iot.pet_flag",
  "slots": {
    "did": "",
    "sn": "",
    "iot_robot_type": "",
    "time_from": "",
    "time_to": ""
  },
  "execute": false
}
```

未知槽必须拒绝。`execute=true` 而对方未授权时，sidecar 直接失败，禁止降级去 L3。

### L1 输出（调用方最低要求）

```json
{
  "ready": true,
  "lane": "L1",
  "status": "ok",
  "trace_id": "",
  "artifacts": {},
  "clarify": null
}
```

`status=clarify`：只许回问当前用户，不许 Hermes 替用户猜槽后自动再执行。

## 2. 知识问答

对标数据智能体的只读知识档，**不是** 整库同步。


| 项     | 约定                                                |
| ----- | ------------------------------------------------- |
| 输入    | `query`（自然语言）、可选 `top_k`                          |
| 输出    | hits（title / snippet / source_id），禁止附带可执行 SQL     |
| 路由    | 「这张表什么意思」「临时需求有哪些」可走本 skill；问数模板走 L1              |
| 与本仓关系 | 知识仍可继续同步进 vault；运行时互调是备份，不是替代 `kb.retrieve` 的发版义务 |


---



## 3. 生成 SQL / 执行取数


| 项   | `chatbi.sql.generate`                        | `chatbi.sql.execute`                               |
| --- | -------------------------------------------- | -------------------------------------------------- |
| 输入  | 主题、已澄清槽、禁止自由 NL 当唯一入口（至少要 `intent_id` 或模板线索） | generate 的计划 id 或签名后的 SQL 句柄                       |
| 输出  | SQL **计划** + 表白名单 + `trace_id`；给人看的摘要不含 SQL  | 规范属性 / 行引用；Chat 出口仍禁止 SQL 原文                       |
| 权限  | 任何已登记对等可读计划（若同事同意）                           | `data_class=restricted`；融合侧无 Hive 行权限时 **禁止** 借路执行 |
| 失败  | clarify 回用户                                  | Guard 失败 → 调用方降级，不自动改 generate                     |


数据智能体接这两档时：D1/D2 黄金关联 **不以** ChatBI 作文或现场 SQL 为准。

## 4. 登记门槛

缺下面任一条，ChatBI 只许当「人在环的聊天框」，不许进 SUNNY 搜索：

1. 至少一个 L1 `template_id` + 槽字典
2. 基址与服务身份（不要同事个人登录）
3. `trace_id` 能回传
4. 执行开关默认 false
5. Card 草稿通过 `scripts/validate_card.py` 且无密钥

sidecar 可以由数据智能体侧代写，ChatBI 业务进程不必改造成 A2A。
