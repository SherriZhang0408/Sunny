# ADR-002 工作空间隔离

| 项 | 内容 |
|----|------|
| 状态 | **已采纳** |
| 日期 | 2026-09-18 |
| 上游 | [ADR-001](./ADR-001-开写前五件事.md) 第 2 条 |

> 拍板原话：Agent 服务账号，不进个人 scratch。

---

## 结论（P0 必须遵守）

1. **调用身份只用 Agent 服务账号。** 票的 audience 是调用方 `agent_id`，不带登录名 / 工号 / 飞书用户。
2. **跨 Agent 调用不进个人 scratch。** 不读、不写、不冒充任何控制台登录名下的会话盘。
3. **对外只落在服务工作区。** 技能走被调方自己的服务账号和环境凭证；审计记 `agent_id` + `trace_id`，不写进某位同学的对话历史。
4. **P0 不分 personal / team / prod 三套空间。** Card 上一个 `workspace` 标签即可（示例 `lab.echo`）。
5. **不做用户代持。** 以后若真有「帮张三查他自己的 scratch」，另开 ADR，默认仍关。

Card 上对应字段：`x-sunny.invoke_identity = agent_service`，`x-sunny.scratch_access = none`。

---

## 和现网三层盘怎么对齐

```text
控制台登录名  →  个人 scratch              ← 跨 Agent 禁止进入
被调方服务区  →  环境凭证 / 已有 HTTP       ← 对外技能走这里
对外 Card     →  已契约化的 skill.id        ← 已登记对等 + 短时票
```

发现仍按 ADR-001：已登记 Agent 可互发现。调用另要短时票，票不能改调 `not_exposed` 里的能力。

---

## 未纳入本 ADR（不挡身份模型）

| 仍开放 | 说明 |
|--------|------|
| 谁能提交 / 更新 / 下线 Card | P0 先按运维代提，不开放 Agent 自注册；需要时再补登记 RBAC |
| 公司 SSO | 仍是 P1；服务账号先由 Registry 签发，不绑个人登录 |

---

## 验收句

1. 任何已登记 Agent 用服务身份调用，**不会** 在某位同学的 scratch 里留下会话。
2. 短时票里没有用户登录名，只有调用方 `agent_id` 与 `skill.id`。
3. 同一张票不能改调 `x-sunny.not_exposed` 里的能力。
4. `workspace` / `invoke_identity` / `scratch_access` 变更必须升 Card `version`，旧票作废。
